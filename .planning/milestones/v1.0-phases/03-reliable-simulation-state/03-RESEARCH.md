# Phase 3: Reliable simulation state — Research

**Researched:** 2026-09-24
**Requirements:** SIM-02, SIM-03, VER-01
**Sources:** Live app/Metal/Xcode sources, Phase 1 baseline, Phase 2 context and validation, Apple MetalKit `MTKView` API documentation.

## Planning conclusion

Keep the existing two-target, shared-renderer architecture. Add a small shared, GPU-independent state contract for selected field, user pause, lifecycle pause, and future tuning defaults/bounds/reset; use it from both controllers and the renderer. Preserve all five GPU fields across a drawable resize with a render pass that samples old ping textures into replacement ping textures using normalized coordinates. Make a paused `MTKView.draw()` presentation render-only, so field switches and resizes are visible without a solver step. Establish a real Xcode-run automated state suite, an offscreen Metal resize regression check, and both-scheme build gates.

## Evidence and architecture

- `Shared/Renderer.swift` has `currentIndex` 0–3 (`density → pressure → velocity → vorticity`), `nextSlab()` and `draw(in:)`; the latter always executes advection, forces, vorticity, divergence, 40 Jacobi iterations and gradient, including when explicitly drawn during pause. `mtkView(_:drawableSizeWillChange:)` allocates entirely new `Slab`s and triple uniform buffers, discarding the image and pressure seed. Contacts use view-point coordinates and `directions` is the previous mouse position.
- `Shared/Slab.swift` ping/pong are `.rg16Float`, render-target and shader-read textures. `Shared/RenderShader.swift` can encode a full-screen pass into a chosen texture. `MetalDevice.sharedInstance` uses one serial `MTLCommandQueue`; a resize must not overwrite/release in-flight state or buffers that the GPU still reads.
- iOS controller tracks touches in `touchOrder`, `positions`, `previousPositions`, `startPositions`, `activeTouches`, delayed `pendingHolds` and renderer's pending taps. Its `willResignActive`/`didBecomeActive` handlers currently force pause and unpause, forgetting user intent. Mac controller uses window coordinates in `mouseDown`/`mouseDragged`; converting via `metalView.convert(event.locationInWindow, from: nil)` avoids assumptions about view origin. Preserve Space/S and iOS double-tap shortcuts.
- Apple documents `MTKView.isPaused` as stopping the automatic draw loop, `draw()` as an immediate delegate draw (never call within draw), and `enableSetNeedsDisplay` as allowing event-driven redraw when the view is paused and this flag is enabled: https://developer.apple.com/documentation/metalkit/mtkview/ispaused, https://developer.apple.com/documentation/metalkit/mtkview/draw%28%29, https://developer.apple.com/documentation/metalkit/mtkview/enablesetneedsdisplay. Call explicit `view.draw()` on a paused field switch or size change (on the UI thread); do not rely on a future frame.
- Phase 2 already added `test_phase02_metal.swift` and `test_phase02_metal.py` to run offscreen passes from the built Mac `default.metallib`. There is **no XCTest target**; `project.pbxproj` lists shared Swift/Metal files separately in both app targets, so new shared state must be added to both and the state test target/scheme must be wired deliberately.

## Recommended implementation details

### State and lifecycle

Use a `Shared/SimulationState.swift` Foundation-only type with `enum DisplayField: Int, CaseIterable` (`density=0`, `pressure=1`, `velocity=2`, `vorticity=3`), a `userPaused` flag, an `inactive` flag, computed `shouldAdvance = !userPaused && !inactive`, `nextField()`, `togglePause()`, `resignActive()`, `becomeActive()`, and `resetTuning()`. A user pause survives inactivity independently of automatic lifecycle suspension. Preserve field on pause/resume/resize. Store tuning as a value type with stable defaults matching the current hard-coded values: scalar input 0.8, ink radius 150 (at scale 1), advection retention 0.998, vorticity curl 0.4 per axis, pressure iterations 40. Choose explicit finite bounds and clamp invalid finite values; non-finite inputs fall back to defaults. Representative bounds for future controls: force and dye 0...2, swirl 0...2, fade/retention 0...1 (default 0.998), radius 1...400, pressure iterations 1...80. Future live-tuning wiring into uniforms/shaders belongs to Phase 5; in Phase 3 the contract's defaults and setters/reset are testable, while solver constants remain unchanged.

`Renderer` owns this shared state; controllers ask it to toggle pause and field and apply `view.isPaused = !state.shouldAdvance`. A paused field change explicitly draws the currently selected slab; `draw(in:)` must branch into presentation-only when state says no advance. During iOS inactivity, save user intent implicitly in `userPaused`, mark inactive, clear all touch bookkeeping/delayed holds and renderer pending contacts/taps, then restore the effective pause state on return. Do not accumulate elapsed wall-clock time: the solver currently advances once per actual draw, not via a `deltaTime`; no catch-up steps are needed. Guard gesture callbacks when inactive and touches while paused; on resume, rebase held drags at the current point before generating force. A true pause should not leave dye/forces queued (including a delayed single-tap recognizer). On Mac, track mouse-held status or rebase the first resumed movement; on iOS, rebase each active touch and cancel pending hold work before resuming.

### Resize preserving GPU state

At a valid change of the logical simulation grid, retain old slabs, allocate replacements for **velocity, density, velocityDivergence, velocityVorticity, pressure**, and encode five full-screen texture-sampling passes into new `ping` textures. Sampling normalized UV over the *entire* old texture maps all old fluid to the new aspect ratio (stretch rather than crop or letterbox). New `pong` needs no copy because the next solver write replaces it. A dedicated `.rg16Float` shader for resampling is preferable to `visualizeScalar`/`visualizeVector`, which alter color. For velocity, scale its x and y components by new/old grid dimensions so a motion measured in cell units remains proportionate when stretched. Keep pressure and vorticity available immediately for a paused field view (do not clear them).

Synchronize reallocation against in-flight draw submissions and triple uniform buffers; one valid approach is to acquire all three renderer semaphore permits before replacing state, encode/commit migration on the same serial command queue, wait for completion, then publish replacements and release permits. Do not wait while owning a permit that a GPU completion needs, or wait on the main thread for a drawable; render migration offscreen. Retain old textures until migration completes and handle command-buffer error before swapping. Avoid repeated allocations on identical grid dimensions, defer zero-sized view callbacks instead of creating zero-sized textures, and initialize at first valid size. Keep grid dimensions in logical view points unless intentionally converting all input/radius math to drawable pixels in the same change; `size` is drawable pixels but current `screenSize`, touch radius and mouse coordinates are view-point based. If a size change occurs mid-drag, rebase previous contact positions and clear pending splats; update positions via view-local event coordinates after the new layout.

### Automated checks and observations

Add an Xcode macOS unit-test target using XCTest (or a deliberately standalone `swiftc`/`xcrun swift` test harness compiling the *production* `Shared/SimulationState.swift`) that executes real production state code. Prefer XCTest with `xcodebuild test -project FluidDynamicsMetal.xcodeproj -scheme FluidDynamicsMetalOSX -destination 'platform=macOS,arch=arm64' CODE_SIGNING_ALLOWED=NO`; create/shared scheme TestAction if auto scheme discovery does not attach the new target. Tests must cover the complete field cycle including wrap, running → paused → field switch while paused → resumed, lifecycle return for initially running and user-paused cases, and each tuning field's default/bounds, non-finite policy and reset after mutations. Avoid tests that duplicate a second implementation of the state contract.

Extend the Phase 2 offscreen GPU harness (or create Phase 3-specific files without changing Phase 2 assertions) to seed a nonuniform density/velocity/pressure texture, run the actual resize shader to a substantially different aspect ratio, read back RG16F data, assert old edges and recognizable center survive plus velocity component scaling, and assert no solver step is invoked for a paused redraw. A shader-only harness does **not** establish integration through `Renderer.mtkView`; supplement with Mac window live-resize (including while dragging and paused) and iPhone/iPad simulator rotation or view resize, pause/field/lifecycle observations. Record manual-only and unobserved device gestures honestly. Rebuild both app schemes after shared changes.

## Risks and constraints

- `RenderShader` uses `.dontCare` load action: fresh ping textures must be fully covered by the resample pass before presentation. Never resample in-place.
- `draw(in:)` currently writes/consumes pending contacts before solving. The paused branch must not consume or store pending input for later. Explicit paused draws must not increment pressure iterations or advect/fade density.
- The old GPU work must complete before old slab references and uniform buffers are replaced. A blocked `semaphore.wait()` on the UI thread can stall live resize; limit waits and verify rapid repeated resizes.
- With a separately compiled shared state source, missing `PBXBuildFile` membership on either app target or on the test target will produce build/link errors. Test scheme discovery must be confirmed with `xcodebuild -list` and an actual `xcodebuild test` run.
- Keep `StaticData`/Metal `BufferData` layout and existing shader entry points aligned, and retain scalar RGB `(0, 0.06, 0.19)`, 0.8 injection, 0.998 fade, `(0.4, 0.4)` curl and 40 iterations in this phase. No new on-screen controls.

Wave 0 must add production-state test infrastructure and a runnable test command before claiming automated coverage. No automated test should claim to simulate a real UIKit touch or prove on-screen fluid appearance based only on compilation. Keep feedback incremental (focused unit tests after state edits, GPU test after resize shader, both builds per wave).
