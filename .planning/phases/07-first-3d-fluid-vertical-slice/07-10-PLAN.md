<objective>
Close UAT gap G-07-5: switching directly between paused 2D lessons (and paused 2D Step) must update the visible canvas. Since 08-03 (commit b4b6be6), `Renderer.redrawIfPaused()` presents paused 2D frames with `drawPresentationOnly(in:)`, reading `view.currentDrawable` outside an MTKView draw cycle. MTKView caches that drawable until its next real `draw()`, so after the first paused redraw each later one renders correct pixels into an already-presented drawable that never reaches the screen. The paused 2D Step drain has the same defect. Reset/state logic is correct; this shared code also affects iOS.

Also fix the UAT side finding from the G-07-4 diagnosis (no gap id): Command-M does nothing while the Simulation Controls utility panel is key.

Purpose: restore the established 2D selection/reset presentation (D-15) and exact visible paused stepping (D-16) without touching the 3D path, the 2D solver or the ABI.
Output: Renderer fix, a headless spy regression, a real-window macOS UI regression, and a panel Minimize forwarder with its UI regression.
</objective>
