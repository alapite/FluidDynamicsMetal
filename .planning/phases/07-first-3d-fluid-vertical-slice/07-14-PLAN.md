<objective>
Close sub-finding (a) of UAT gap G-07-2: returning dye is too dim to read. The 07-12 user statement was "the brightness as it returns is very low, and so it's hard to interpret what is going on". The 07-11 measurements explain it: the returning slice peak was 0.201 at step 600, which the linear black→amber→cream palette draws at about 40% of amber, roughly L* 28. Implement gap-round user decision 1 (2026-11-21): brighten low concentrations in the display mapping with one fixed, documented transfer curve, keep the D-05 amber palette, keep the legend honest (D-06/D-13), and leave dye data untouched.

Design choice (Claude's discretion within decision 1): the transfer is a fixed square root, d = sqrt(clamp(c,0,1)), placed in front of the unchanged palette stops. A "documented auto-range" option was rejected because 07-UI-SPEC ("no frame-maximum normalization or exposure animation") and 08-UI-SPEC ("No per-frame normalization, adaptive exposure") both forbid it, and an auto-range would hide genuine thinning (D-09). The square root maps the 07-11 returning peak 0.201 to d = 0.448, close to the amber stop, while keeping 1% numerical haze dark (d = 0.1). 08-UI-SPEC permits this only as "an explicitly verified color-path amendment". This plan verifies the colour path against independent expectations, and 07-16 Task 3 writes the UI-SPEC amendment text. The inspection contract hash-pins the old palette clause, so it gets a dated amendment and every pin is updated.

Also repairs a latent break left by 07-11 that would otherwise fail 07-13's integration category. test_inspection3d_reference asserts PHASE7_HASH, the numerical contract's complete-file hash, which is still the pre-07-11 value (prefix 5fdc33b8). Every spatial fixture runs that test as its reference step, so they all fail at HEAD 27713a9.

Purpose: make the fade-and-return interpretable without faking numerical state.
