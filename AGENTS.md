# Repository notes

- Open `FluidDynamicsMetal.xcodeproj`; its two app schemes are `FluidDynamicsMetaliOS` and `FluidDynamicsMetalOSX` (capitalization matters). There is no Swift package or test target; verify changes by building the affected scheme and exercising the app.
- For a focused macOS build: `xcodebuild -project FluidDynamicsMetal.xcodeproj -scheme FluidDynamicsMetalOSX -configuration Debug -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO build`. The project specifies Swift 4 and macOS 10.13; newer Xcode SDKs may reject that deployment target. Override it with `MACOSX_DEPLOYMENT_TARGET=<supported-version>` for local verification rather than silently changing project settings. Building the Metal source also requires Xcode's Metal Toolchain (`xcodebuild -downloadComponent MetalToolchain` if missing).
- `Shared/` files are compiled directly into **both** app targets, not a separate module. `FluidDynamicsMetaliOS/` and `FluidDynamicsMetalOSX/` each own their storyboard, app delegate and input-handling `RenderViewController`; both controllers install the shared `Renderer` as the `MTKView` delegate.
- The simulation pipeline lives in `Renderer.draw(in:)`: advect velocity/density, apply input forces, compute/constrain vorticity, compute divergence, run 40 pressure iterations, subtract the pressure gradient, then display a selected slab. `Slab` ping/pong textures swap after each pass. Shader entry-point names are string literals in `Renderer.swift` resolved from `Shared/Shaders.metal`; keep those names and the Swift `StaticData` / Metal `BufferData` layouts aligned when editing either side.
- Simulation parameters are hard-coded in `Renderer.swift` and `Shaders.metal` (there is no settings UI). See `README.md` for the platform-specific gestures/keys used to pause and switch displayed fields during manual checks.
