# Repository notes

- App and shared code live under `Sources/{macOS,iOS,Shared}`. XCTest sources live in `Tests/Unit` and `Tests/UI/{macOS,iOS}`; standalone Python/Swift regression checks live in `Tests/Integration`. Keep Xcode group paths and project-relative Info.plist/entitlements settings aligned with this layout.

- Open `FluidDynamicsMetal.xcodeproj`; its app schemes are `FluidDynamicsMetaliOS` and `FluidDynamicsMetalOSX` (capitalization matters). Both require Swift 6.2+ (Xcode 26+), use Swift 6 language mode (`SWIFT_VERSION = 6.0`), and target minimum iOS/iPadOS 26 or macOS 26 (Apple Silicon). There is no Swift package; the project has Mac state tests plus Mac and iOS HUD UI test targets.
- Build Mac with `xcodebuild -project FluidDynamicsMetal.xcodeproj -scheme FluidDynamicsMetalOSX -configuration Debug -destination 'platform=macOS,arch=arm64' CODE_SIGNING_ALLOWED=NO build` and iOS Simulator with `xcodebuild -project FluidDynamicsMetal.xcodeproj -scheme FluidDynamicsMetaliOS -configuration Debug -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build`. No deployment-target or Swift-version override is needed. The Metal source requires Xcode's Metal Toolchain (`xcodebuild -downloadComponent MetalToolchain` if missing). `./build-macos.sh` copies a launchable Mac Debug app into the project root.
- `Sources/Shared/` files are compiled directly into **both** app targets, not a separate module. `Sources/iOS/` and `Sources/macOS/` each own their storyboard, app delegate and input-handling `RenderViewController`; both controllers install the shared `Renderer` as the `MTKView` delegate.
- The view-facing `Renderer.draw(in:)` delegates one step to `FluidSimulation.encodeStep`: advect velocity/density, apply input forces, compute/constrain vorticity, compute divergence, run 40 pressure iterations, subtract the pressure gradient, then recompute final vorticity for display. `FieldVisualization` renders the selected field with GPU statistics; `ParticleSystem` maintains passive tracers and history. `Slab` ping/pong textures swap after each pass. Shader entry-point names are string literals in `Renderer.swift` resolved from `Sources/Shared/Shaders.metal`; keep those names and the Swift `StaticData` / Metal `BufferData` layouts aligned when editing either side.
- Both apps expose named fields, Run/Pause, Step, Reset/Restart, three deterministic 256-square-grid lessons, arrows/particles/trails, and collapsible Force/Dye/Swirl enhancement/Dye fading/Motion damping tuning. Lessons complete at 600 steps; counters measure steps, not physical time. Run Mac state/HUD tests with `xcodebuild test -project FluidDynamicsMetal.xcodeproj -scheme FluidDynamicsMetalOSX -configuration Debug -destination 'platform=macOS,arch=arm64' CODE_SIGNING_ALLOWED=NO`, iOS HUD tests with the iOS scheme and an available simulator ID from `xcrun simctl list devices available`, and all integration regressions with `python3 -m unittest discover -s Tests/Integration` after building Mac. See `README.md` for separate Mac/iPhone/iPad manual steps. A newer macOS host cannot verify macOS 26 runtime behavior; physical-device two-finger checks remain NOT TESTED without hardware.
